# React UI/UE 设计规范

本规范适用于后台、控制台、门户和工作流等 React 产品。它定义可复用的设计过程与验收口径，不规定任何产品的页面、菜单、颜色、文案或业务操作。设计系统是产品资产；React 只决定如何实现交互和状态，不替代信息架构设计。

## 1. 先定义任务，再设计页面

每个页面写清一个首要用户问题、目标角色、完成条件和下一步。页面应先呈现任务所需的状态与行动，再呈现次要详情。一个页面可以有多个模块，但每个模块要说明它回答的问题、数据来源、更新时间、权限和跳转目标。不要用卡片数量或图表数量代替信息层级。

新页面的设计说明至少包含：

| 项目 | 必须回答 |
| --- | --- |
| 用户任务 | 用户为什么来到这里，最短完成路径是什么？ |
| 信息层级 | 页面标题、当前状态、主要行动、摘要、工作区和详情如何排序？ |
| 状态矩阵 | 首次加载、刷新、空、过滤后空、无权限、离线、错误、冲突、提交中、成功、部分成功如何呈现？ |
| 操作契约 | 每个动作的输入、结果、影响、可撤销性和错误恢复是什么？ |
| 内容与数据 | 单位、时间范围、时区、精度、采样和“不知道”的状态如何显示？ |
| 布局与设备 | 不同 CSS viewport、缩放、触控、键盘与折叠屏如何重排？ |
| 验收证据 | 哪些交互、可访问性和视觉状态需要测试/截图？ |

## 2. 页面、导航与复杂工作流

- 稳定的导航区域承载位置感；页面标题应说明当前对象或任务，避免只有模块代号。深链接能恢复关键筛选、分页、选中对象和返回路径。
- 一个视区只强调一个主操作。危险操作必须说明目标、影响和恢复方法；不可逆操作要有明确确认与结果反馈。普通浏览和调整不应被多层确认打断。
- 列表先服务于“找到对象、判断状态、执行动作”。高密度表格应有清晰列标题、单位、排序/筛选状态和行操作；窄屏改为摘要卡片或详情视图，不强迫横向滚动完成核心任务。
- 复杂表单按用户心智分组，逐步揭示条件字段。标签使用正式业务名称，帮助文本解释单位、适用条件和后果；协议字段名不直接充当界面标签。
- 新手引导使用可跳过的上下文说明与合理默认值；错误消息给出可执行的修复动作。熟练用户保留快捷路径，不强制重复看教程。

## 3. 反馈与状态

同一操作的生命周期应可辨认：尚未开始、正在进行、结果确定、可恢复失败、需要人工处理。加载保留页面结构并避免布局跳动；刷新已有数据时可保留旧值，同时标记其时间和刷新状态。无数据不是零，未授权不是空，网络断开不等于服务不可用。

错误反馈包含发生位置、影响范围和下一步；必要时展示安全的请求/追踪 ID。表单保留用户输入，明确指出字段错误与跨字段冲突。提交成功后让用户看到实际状态或后端确认结果，不只显示“已成功”的 toast。后台任务说明排队、执行、完成和失败的阶段。

多个状态源不能混淆：浏览器网络、API 健康、数据时效、权限与业务告警分别命名。图表不在无样本时绘出貌似真实的平线；演示数据必须显著标记。

## 4. 可访问性、国际化与内容

- 使用语义化标题层级、landmark、原生控件和可见标签。图标按钮有可理解的名称；状态不只靠颜色传递；动态结果选择恰当的 live region。
- 所有核心任务可只用键盘完成。焦点在弹窗开启、关闭、导航和错误出现时有确定去向；焦点轮廓清晰，固定顶栏不遮挡焦点。触控目标按产品设备策略提供足够尺寸和间距。
- 验证浅色、深色、高对比、放大文字、浏览器缩放与 `prefers-reduced-motion`。动画只解释状态改变，不能阻塞操作或隐藏结果。
- 所有用户可见文案进入翻译资源。日期、数字、百分比、货币、复数和时区使用 locale-aware 格式化；布局为翻译扩展留空间，并预留 RTL 适配能力。
- 文案描述用户可见的行为，避免内部类名、接口名和技术错误堆栈。空状态说明原因和下一步，权限不足说明所需能力但不泄露受保护对象。

## 5. 响应式与图表

以 CSS viewport 和容器可用宽度为准，不按手机型号或物理分辨率判断。窄屏优先保持任务顺序和主操作可达；中等宽度减少并排区域；宽屏限制文本/表单最大宽度，不让 4K 页面无限拉伸。断点是布局变化点，不是固定设备名。至少核对手机竖横屏、平板、普通桌面、宽屏、高 DPI 与常见浏览器缩放。

图表必须提供标题、指标单位、时间范围、数据时效和有意义的空/错误状态。颜色来自皮肤的语义 token；轴、网格、阈值线、标注和 tooltip 使用同一套格式化与皮肤。对照图表应明确系列含义、基线、变更点和可比较的单位；不能用两条不同尺度的曲线暗示直接相关。高频数据需要采样/窗口上限，并为非视觉使用提供文字摘要或数据表。

## 6. 视觉系统与 SCSS 皮肤

先确定语义 token，再构造页面。至少覆盖背景/表面层级、主次文本、边框、交互、状态色、图表色、排版、间距、圆角、阴影、动效和布局尺寸。产品可以有自己的视觉语言，规范不指定某套组件库或默认配色。

皮肤文件只给语义 CSS 自定义属性赋值；组件样式只消费这些属性。浅/深色和品牌变体必须保持 token 名称及语义一致。SCSS 用于组织 token、mixin 和局部样式，运行时切肤由 CSS 自定义属性完成。主题切换、首屏防闪烁、图表适配和样式目录的工程责任见[项目骨架规范](REACT_PROJECT_SKELETON.md)。

## 7. 交付检查

设计交付给出页面地图、主要任务路径、状态矩阵、响应式重排行为、语义 token、组件边界、正式文案/翻译键与可访问性要求。开发验收覆盖核心路径和恢复路径；视觉核对至少包含默认、窄屏、深/浅皮肤、键盘焦点、错误/空状态。构建通过只能证明资源可产出，不能证明页面任务可用。
